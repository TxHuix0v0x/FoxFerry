# FoxFerry 安装与升级

订阅聚合与分流助手，Windows x64，当前版本 0.3.0。

## 运行

- 最终安装包：`release/FoxFerry-0.3.0-x64-setup.exe`，未签名，安装器未执行，由用户自行安装。
- 免安装入口：`release/win-unpacked/FoxFerry.exe`。必须保留整个 win-unpacked 目录，无需安装 Node.js 或 npm 依赖。
- 项目根目录的 `启动助手.vbs` / `启动演示.vbs` 优先使用上述 EXE。缺少构建时才回退源码 Electron，须先恢复开发依赖。

安装器、默认目标文件夹、EXE、快捷方式、卸载列表和内部新建标识统一使用 FoxFerry。默认目标为本机 Programs 下的 FoxFerry，也可选择其他磁盘。新数据默认位于 `%APPDATA%/FoxFerry`，演示为 `%APPDATA%/FoxFerryDemo`。

升级 GUID 保留以识别已有安装；对旧默认目标目录进行 FoxFerry 名称修正。已有旧配置仍可读取：若新数据目录尚无 state.json 而旧目录有，则继续使用原目录，不自动复制、移动、覆盖或删除设置。旧配置归属字段也只做兼容读取，新生成配置统一使用新标识。

## 升级

1. 从托盘退出助手，私密备份实际使用的数据目录（新建默认 `%APPDATA%/FoxFerry`，演示为 FoxFerryDemo；旧配置可能仍使用原目录）。其中可能含订阅凭据、背景及生成配置，不提交代码仓库。
2. 在 Clash Verge 中另行备份其订阅与配置，助手备份不包括 Verge 的全部数据。
3. 使用保持相同身份的新安装包安装到原位置，通常无需先卸载；降级前确认数据版本兼容。
4. 启动核对订阅、线路、背景和联动。连接历史仅在本次运行内存中，退出即清空。卸载器配置为保留用户数据。

## 后续开发

维护文件保留 src、狐狸素材、scripts、test、CI、examples、有效许可证、package.json/lock、当前说明与启动入口。回归测试源码属于升级保障，保留；运行报告、截图、研究副本、旧素材和构建调试输出均不保留。安装包仅包含运行文件与指定用户文档，不打包验证记录。

开发、测试或重新构建前使用 Node.js 24 LTS 执行：

```powershell
npm ci
npm run check
npm test
```

依赖缓存 node_modules 已清除，可通过锁文件恢复。测试脚本按需创建隔离 .local，测试后可删除；清理含 junction 的测试目录时，只删除链接自身，不沿链接删除最终发布目录。

内核回归不依赖 .research 源码。另行获取 Mihomo EXE 后执行：

```powershell
$env:MIHOMO_BINARY = 'D:\工具\mihomo.exe'
npm run test:core
```

CI 获取固定 v1.19.33 内核。不要用真实订阅或系统网络设置代替隔离回归。

## 0.3.0 更新

- 新增节点切换记录：每份订阅在「订阅管理」中记录自动切换、手动切换、临时加速与恢复路线的时间、线路、节点变化和原因，方便确认 FoxFerry 实际怎样换线。
- 新增流量历史：按小时汇总的观测流量保存最近 1 年（近 48 小时按小时、更早按天），重启不清零；运行概览的「观测流量历史」默认折叠，展开后提供「当天 / 近 24 小时 / 近 7 天 / 近 14 天 / 近 30 天 / 全部」切换，柱状图按小时或按天显示，「全部」为整年日历热力图。
- 延迟查询提速：手动查询改为 20 路并发、单节点 2.5 秒超时，整份订阅通常 1 秒级返回。
- 修复：流量柱状图在严格内容安全策略下的显示异常。


## 0.2.9 更新

- 修复：进程与配置发现失败时不再暂停调度。该步骤只用于观察，失败时保持上次结果并记录一条「运行提示」，路由继续工作，无需手动重新接入。
- 修复：错误提示不再显示原始命令行，改为可读说明。


## 0.2.8 更新

- 状态标签可点击：调度暂停或异常时，右上角状态标签直接变为「点击重新接入」，效果等同「首次接入」最后一步，不必再翻到向导底部。
- 节点延迟查询：订阅管理新增「查询节点延迟」，执行后自动展开节点表，新增「延迟」列显示毫秒数或「超时」；选线窗口也有「查询延迟」，节点下拉框直接带延迟。查询并发由 4 提到 10，整份订阅通常 1–2 秒。
- 自动选线：原「启用同国自动」改为开关；新增「自动最低延迟（不限国家，定时重探）」，按设置中的延迟检查周期反复探测并切到最快节点。两者与「临时加速」互斥，保存后重新打开窗口会按当前模式回显；手动改订阅或节点会退回手动锁定。
- 风险提示：自动最低延迟会跨国家跳转节点，出口 IP 变化可能导致部分网站判定异常登录并封禁账号，下载、上传与登录态也可能中断。
- 跟随联动更稳：启动前先清理残留的后台助手，等待时间由 4 秒放宽到 8 秒，首次失败自动重试一次，减少偶发的「联动未启用」弹窗；后台轮询间隔由 2.5 秒调整为 5 秒，降低常驻开销。
- 连接历史有界：只保留最近 2000 条已结束记录，活动连接不淘汰；列表上方显示已清理条数，长时间挂机内存不再持续增长。
- 许可：`LICENSE` 恢复为标准 MIT 全文，素材与第三方声明统一放在 `NOTICE.md`，GitHub 可正确识别为 MIT。
- 文档、截图与启动器路径同步更新。


## 0.2.3 联动修复

修正自定义登录启动项读回误判；核对项名、路径、Windows 解析后的完整参数及启动批准状态。登记或 watcher 启动失败会回退本应用原登记并回滚设置；手动关闭立即撤销登记并停止 watcher。Windows 自行禁用的项不在启动时擅自重启用，用户可在设置中重新明确开启。


升级时先从托盘退出 0.2.2，再安装到原目录，启动后确认页脚 0.2.3，再勾选联动。无需删除订阅或背景。

0.2.7 将本地许可、项目仓库与手动稳定更新检查集中到独立「关于」页。仅用户点击时访问 GitHub，不自动下载或安装，不上传订阅数据。远程仓库和稳定 Release 的公开可用性尚待维护者创建发布后验证。


0.2.7：项目仓库、许可和检查更新入口位于侧边栏「关于」页；普通结果5秒、错误8秒后收起，悬停/焦点暂停，新版提示保留到离开关于页。连接按首次采样发现时间降序，结束时间另行详情显示。

0.2.7：侧边栏改用22px实心矢量图标和16px深色文字，选中项跟随主题；关于页新增支持卡片，赞助入口按当前约定打开项目仓库。
