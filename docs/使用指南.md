# FoxFerry 使用指南

## 启动与升级

使用安装版时从本项目稳定 Release 下载安装 EXE，核对 SHA256 后安装。免安装版须保留完整 win-unpacked。升级前退出 FoxFerry，安装到原位置并保留用户数据。

维护源码的用户：先从托盘**退出旧助手**，双击 **`启动助手.vbs`**；试用演示双击 **`启动演示.vbs`**。这两个入口优先启动 `release/foxferry-0.2.7/win-unpacked/FoxFerry.exe`，缺少构建时才回退到源码 Electron；不经过 CMD/npm，不出现黑窗口。源码调试用 `npm start` 或诊断 CMD，修改源码后需重建才能由默认入口使用。原 CMD 改名为 `诊断启动助手.cmd` / `诊断启动演示.cmd`，仅供主动查看终端日志。

免安装版无需 Node.js 或开发依赖，保留完整 `win-unpacked` 目录即可启动。项目已清除 `node_modules` 缓存；只有开发、测试或重新构建前，才需要 Windows x64、Node.js 24 LTS 并恢复依赖：

```powershell
npm ci
node -e "require('electron')"
```

第二条命令确保首次 Electron 下载完成，之后双击 VBS 即可。依赖缺失时启动器会弹出提示；支持项目路径包含中文、空格和逗号。若系统禁用 Windows Script Host，请使用原生 EXE，不需要更改系统安全设置。

安装版：`release/foxferry-0.2.7/FoxFerry-0.2.7-x64-setup.exe`。免安装版：`release/foxferry-0.2.7/win-unpacked/FoxFerry.exe`。两者均原生无窗口启动，安装包未签名，本次未执行安装或远程发布。

首次用 0.2.x 打开 v1 旧数据时，先验证并备份原始 `state.json` 到用户数据目录的 `backups/state-v1-*.json`，再原子升级至 v2。保留订阅、ID、规则顺序、共享关系和节点选择；升级自身**不会自动接入调度或重载内核**。请到「首次接入」重新确认。备份失败或旧数据无效时停止升级，保留原数据；无需重建原有订阅。旧版不能直接读取 v2，新版用户如需降级，先退出助手并恢复对应 v1 备份。

演示内置三家模拟订阅、同名节点与模拟连接，数字为合成数据；不接触真实 Mihomo。演示数据与真实数据分目录保存，演示重启会重置条目。

安装器、默认安装目录、程序 EXE、快捷方式、内部包名和任务栏标识统一为 FoxFerry。新数据默认位于 `%APPDATA%/FoxFerry`，演示使用 `%APPDATA%/FoxFerryDemo`；仅为读取已有设置保留旧目录兼容，不移动、覆盖或删除用户数据。升级识别 GUID 保留，已有安装可由安装器识别。最终路径、校验值及安装步骤见 [安装与升级](安装与升级.md)。

## 首次接入

1. 启动你原有的 Clash Verge，在助手中打开「首次接入」→「自动发现」。优先尝试运行配置中的命名管道，并兼容同一用户/渠道的独立模式和服务模式管道；只通过 `GET /version` 验证可用性。管道不可用时，仅尝试运行配置明确给出的本机 HTTP，不扫描端口或其他用户接口；认证失败不会触发替代接口。便携版可手动选择配置目录和 Mihomo 可执行文件。
2. 「读取已有订阅」只读引用 Verge 的节点缓存，不保存或请求原有订阅地址。Verge 继续负责更新；助手约每 30 秒观察缓存结果。也可在「订阅管理」添加 HTTPS 或本地 YAML，由助手默认每日更新。
3. 在「分流管理」设置默认线路并点击「添加分流」，先选择应用 .exe 或填写网站域名；需要独立线路时展开高级选项。主副分流预设保留，仍只补充缺失项。
4. 点击「校验并生成」。助手用本机 Mihomo `-t` 在隔离目录校验，生成用户数据目录下的 `assistant-owned.yaml`。在 Verge 新建**本地**订阅，将此文件导入或将内容粘贴到本地订阅编辑器，命名为「助手专用」。**保留原有订阅，不覆盖原文件。**
5. 在 Verge 中启用该专用配置及**规则模式**，核对端口、TUN、DNS。回到助手点击「确认已启用，接入调度」。归属标记、策略组、实际规则均通过后才开始调度。
6. 用「实际连接」表核对命中线路、实际订阅和节点。应用分流依赖内核识别本机进程，系统代理未必覆盖全部应用；需要覆盖的应用须自行使用已有代理/TUN，助手不会替你开启系统代理或 TUN。

助手后续维护导出文件和 Verge 中**当前启用且归属匹配**的专用本地配置副本，不写 `profiles.yaml`、原订阅文件或其他配置。更新保留运行配置中的端口、TUN、DNS 等字段；节点日常切换仅调用策略组接口。若改用其他配置、模式改变、规则被扩展覆盖、选择被其他界面改动或内核重启，会暂停，需重新核对后确认接入，不与 Verge 争写。

调度暂停或异常时，页面右上角的状态标签会变为可点击的「重新接入」；点击即执行与「首次接入」最后一步相同的确认接入，不必再翻到向导底部。点击后仍需 Verge 中启用的是归属匹配的专用配置。

## 添加分流与高级设置

在「分流管理」点击「添加分流」：

1. 选择「应用」并选择实际运行的 `.exe`，或选择「网站」填写域名。名称自动填入，可修改。
2. 不填高级选项时，使用**跟随默认线路**；主订阅或默认节点调整后一起生效。
3. 展开「高级选项」，可增加另一个匹配条件；同时填写应用和网站时两者都要满足。同类多个路径、旧进程名或域名采用“或”。旧规则保留原有按进程名的匹配方式，选择新 .exe 时会清除旧进程名，改为精确路径匹配。
4. 勾选「为本条分流单独设置线路」，再选择订阅、节点、自动/手动、锁定/允许国家、候选节点和速度提醒。空闲恢复参数沿用全局设置。
5. 保存即可，不需要另建场景。取消勾选独立设置可恢复跟随默认线路。

完整路径匹配区分同名程序，支持中文、空格、括号及逗号。选择实际产生网络连接的可执行文件；程序更新或移动路径后需要重新选择。应用与网站组合仍受内核进程识别能力影响。

主界面或托盘「快捷切换线路」先选择默认线路或分流条目，再选订阅和节点。某条跟随默认或复用旧共享线路的分流被单独切换时，会自动隔离；不会修改默认线路或其他条目。直接切换「默认线路」则影响所有跟随它的条目。旧的未绑定内部线路保留，不自动删除。

## 调度与连接查看

- 基础局域网 DIRECT 和原配置可识别的基础直连规则优先保留；其余分流按显示顺序匹配，未匹配代理流量进入默认线路。复杂嵌套直连逻辑需自行检查迁移。
- 自动选择限制在当前订阅、候选列表、允许国家和锁定国家内；未知国家不参与。名称标注与实际出口检测分开显示，出口检测仅在用户点击后通过独立本地内核向 Cloudflare 发送少量流量。
- 默认每 5 分钟探测延迟，容差 50ms、驻留 5 分钟；失败可在同范围提前切换。没有可用候选时保持原路线并提醒，不自动改用主订阅或 DIRECT。
- 手动选择后锁定，直到重新启用自动。提醒不回应就不切换；速度提醒线默认关闭，超线不代表节点满载，延迟也不代表带宽。
- 流量按每秒连接累计计数增量统计，默认 5 秒窗口；首次观察以当前计数为基线。场景、应用及实际订阅归属仍由现有后台引擎统计，不等同机场账单。
- 定向重连只删除对应连接 ID，不调用清空全部连接。首次隔离共享线路时，只处理能明确归属于该分流的连接，其他条目、直连和无法识别归属的连接均保留。
- 临时加速默认低于 16KiB/s 持续 120 秒后恢复原路线，也可手动恢复；不关闭旧连接。恢复原节点和重新改成「跟随默认线路」是两个不同操作；原节点已移除时提示手动选择。速度提醒弹出后选择「临时加速」仍沿用此机制。
- 「选择路线」中可用「查询延迟」对当前订阅的全部节点各发一次延迟探测，节点列表会直接显示毫秒数或「超时」；「订阅管理」的「查询节点延迟」同样会展开节点表并填入延迟。延迟只代表一次小请求的往返时间，不代表带宽、稳定性或晚高峰表现。
- 「选择路线」中的「自动最低延迟」会跳过国家限制，按「设置 · 延迟检查周期」（默认 5 分钟）反复探测并自动切到延迟最低的节点。节点频繁跳转会让出口 IP 变化，部分网站和应用可能判定为异常登录并封禁账号，下载、上传和登录态也可能中断；不需要时改回「手动锁定」或「启用同国自动」。
- 提醒有效期 2 分钟；规则、选择、暂停或内核重启后旧提醒失效。

「实际连接」保留本次运行中观测到的连接，其中已结束记录最多保留 2000 条（活动连接不计入此上限，超出时按发现时间清理最早的已结束记录，列表上方会显示已清理条数）。连接消失后标记「已结束」，保留最后采样的线路、实际订阅、节点及累计上传与下载。按首次采样发现时间降序、同毫秒按 ID 稳定排序，连接结束不改首次时间或重新分组，每页 10 条，不截断前 100 条；表格固定容纳 10 行，页码可直接跳转。状态旁始终显示首次采样发现的日期时间；已结束状态可聚焦查看明确的结束时间说明，悬停可查看完整时间详情。

可用表格上方的「订阅」选择全部、某个主/副订阅或未归属/直连。筛选只影响列表与条数，不改变分流和流量累计；切换订阅回到第一页，暂停状态保持同一份完整快照。主订阅连接很多时，选择副订阅即可直接查看其连接。

默认实时第一页；翻页自动固定完整快照，其他速率统计继续更新。「暂停刷新」固定当前列表；「刷新快照」取得最新列表、保留并修正页码；「恢复实时」返回第一页。暂停时显示采样时间，快照中的活动连接可能已经结束。恢复实时会更新状态，已结束记录仍保留。

记录只保存在内存，暂停调度、重新接入和关闭主窗口到托盘均不清空；从托盘选择「退出」或结束整个助手进程后清空，下次启动重新记录。不会写入订阅、路由配置或日志账单。仅能保留采样实际看到的连接，无法补回升级前已消失的记录；结束时间是采样发现的时间，累计流量是最后观测值，不保证等于文件最终大小。

后台仅传输当前页的 10 条连接；实时摘要与订阅/规则分开读取，订阅、配置、能力或延迟结果变化时才刷新静态数据。暂停浏览时只在主进程保留一份完整冻结快照，恢复实时后释放。完整会话历史仍随连接数增长，分页不代表历史内存有固定上限。

「按应用汇总本次观测流量」展开后不会被每秒刷新合上。展开状态、连接页码和暂停状态在本次界面会话及页面切换中保留，重启恢复默认；不会写入订阅或路由配置。

## 背景设置

进入「设置」的「背景设置」，选择霁雪、桃夭、杏霞、桂月、碧汀、藤烟、苔影、远岚或暖玉。默认使用初版近白底；色块、图片及其参数即时预览并自动保存，显示「背景已自动保存」后重启仍会恢复。切换纯色与图片会保留上次图片和参数；「恢复默认背景」仅重置背景选项。

图片使用系统文件选择器选择 PNG、JPEG 或 WebP，不超过 20 MiB、边长不超过 8192 像素且总像素不超过 2400 万；可以调节图片不透明度、模糊及填充方式。助手将图片解码后复制到自身用户数据目录的 `backgrounds` 中，不修改原图；移除图片或恢复默认会取消引用，不删除已复制的资源。图片缺失时会回退到所选颜色。

「面板不透明度」和「面板毛玻璃模糊」控制卡片与面板的底色，图片和纯色背景均可使用；文字和按钮不会跟着变透明。默认不透明度为 100%、模糊为 0 px；设置较低的不透明度后可增加毛玻璃模糊，调整后自动保存。

「Clash Verge 联动」开关和「调度参数」也会自动保存；调度值无效时会提示且保留上次保存的值。「恢复默认调度参数」仅重置调度参数，不更改联动或背景。

采样间隔实际控制后台采样周期，运行中修改即可生效；一次采样完成后等待所设间隔，不累积并发任务，速度按实际经过时间计算。隐藏或最小化主窗口后停止界面刷新，显示时立即更新；后台采样、提醒、同国选择与临时加速恢复继续运行。暂停调度时停止采样计时器，重新接入后恢复。

背景使用受限本地资源地址，不在前端累计缓存 Base64。新导入图片附带最长适配 2560×1440 的等比例显示副本；原尺寸居中及超过该像素尺寸的高 DPI 窗口读取原图。已有图片缺少副本时使用原图。移除引用仍不删除内部图片，反复导入的磁盘空间会增长；默认模糊仍为 0，硬件加速策略保持不变。

## 托盘与 Clash Verge 联动

关闭主窗口进入托盘；双击托盘或选择「打开主界面」恢复窗口。「快捷切换线路 → 默认线路／分流条目 → 订阅 → 节点」可在主窗口隐藏时操作，显示当前订阅、节点、手动／同国自动模式及「跟随默认」关系，也可启用同国自动选择。直接切换默认线路影响跟随它的条目，单独切换某条分流沿用隔离逻辑；快捷操作不主动断开已有连接。

每次右键打开菜单都从当前内存生成，不增加后台轮询或测速。未接入、已暂停时线路操作禁用；失效节点不再列出，空订阅显示「没有可用节点」。菜单打开后节点失效或切换失败会提示，保留实际状态。托盘保留暂停调度和退出。

桌宠功能已移除；旧配置的 `preferences.pet` 和 `preferences.position` 加载时忽略，新保存不包含这些字段，其他设置不重置。狐狸 Logo 继续用于界面、任务栏和托盘。旧构建已清理，最终构建位于 `release/foxferry-0.2.7/`。安装和后续升级说明见 [安装与升级](安装与升级.md)。

设置中可开关「跟随 Clash Verge 启停」：安装版登记一个当前用户的登录启动助手，后台观察 `clash-verge.exe` 进程；最小化到托盘不会退出助手。两次连续观察到进程退出后关闭助手，后台启动助手保留，等下次 Clash Verge 启动。手动退出后同一 Clash Verge 进程会话不重复拉起。

联动默认关闭，开发和演示不登记系统启动项；开发版勾选后仅启动本次后台观察进程，下一次登录需手动启动。关闭联动后观察助手会自行退出。请在卸载前关闭联动；卸载不删除用户数据。

## 数据与恢复

新数据默认位于 `%APPDATA%/FoxFerry`；演示位于 `%APPDATA%/FoxFerryDemo`。已有旧版配置时可继续从原目录读取，避免订阅和设置丢失。可用 `--data-dir=绝对路径` 指定隔离目录。

`state.json` 保存版本化状态、节点凭据与助手订阅地址；`assistant-owned.yaml` 是专用配置，`.previous` 为上一有效配置，`transaction.json` 仅在配置或选择保存事务期间存在。日常切换会保存专用组的首选顺序及手动模式，不完整重载内核。敏感文件不进入源码或安装包。它们是当前用户可读的本地明文，依赖 Windows 用户目录权限，分享前须脱敏。界面不接收节点密码和订阅链接的已有值，错误信息隐藏链接、凭据及内核原始错误。

更新顺序：生成→隔离内核校验→确认归属→记录事务→原子替换专用文件→应用→验证→保存状态。失败回退本地文件、场景选择和运行配置；回退失败则暂停并提示启用原订阅。断电/进程中断后，下次启动先恢复本地有效快照并关闭自动接入，再由你重新启用专用配置确认。原有源订阅不被覆盖。

## 开发、测试与构建

```powershell
npm run check       # 所有 JS/CJS 语法
npm test            # 规则、调度、存储、命名管道、恢复等自动测试
node scripts/tray-smoke.cjs # 隔离托盘菜单、旧配置和退出验证
npm run test:ui     # Electron + Playwright，隔离演示，截图在 .local
npm run test:launcher # Windows 无窗口入口、重复启动、中文空格路径
npm run test:core   # 已有本机 Mihomo + 隔离配置 + 本地限速模拟代理
npm audit
npm run build      # Windows x64 NSIS，--publish never
npm run test:package # 校验包内容与免安装程序启动
npm run source     # 使用显式白名单生成源码 ZIP + SHA256
```

`test:core` 自动发现本机二进制，也可指定 `$env:MIHOMO_BINARY = 'D:\路径\mihomo.exe'`。内核需另行获取，不再保留 `.research` 上游源码；通过 `MIHOMO_BINARY` 指向实际 Mihomo EXE（CI 获取固定 v1.19.33）。测试不启动原 Verge，不使用真实订阅，关闭 TUN 和 DNS。进程分流验证使用分别命名为 Chrome/Edge/IDM/qBittorrent 的 Node 测试客户端，可确认 Mihomo 的进程识别与分流，不等同真实浏览器/下载器体验测试。

[Windows CI](../.github/workflows/windows.yml) 可在以后由你选择的仓库中运行测试与构建，只上传构建产物，不发布 Release。首次构建需下载 Electron / NSIS 工具链。源码归档须用显式文件清单，排除 `.local`、`.research`、`node_modules` 和 `release`；切勿直接分享整个工作目录。

## 当前限制

- 只支持含非空 `proxies` 的 Mihomo YAML；不做 Base64、URI、仅 provider 配置转换。协议支持以所选 Mihomo 的实际校验为准；需要相对证书文件或其他外部资源的节点可能无法通过隔离校验。
- 基础 DIRECT 继承支持 IP-CIDR/IPv6、GEOIP、GEOSITE、DOMAIN/SUFFIX/KEYWORD、RULE-SET 及其 provider。复杂嵌套直连逻辑、脚本、链式代理和机场扩展不自动搬运，需检查并转为场景规则；中国直连依赖原运行配置已有的基础规则及 geodata。
- 不精准区分浏览器网页内下载与浏览；不承诺旧连接迁移、跨机场零重连、出口 IP 不变或避免网站风控。
- 流量统计为进程内观测，不保存历史账单；连接完成快于采样周期可能漏记。连接记录仅在本次进程内存保留，退出后不恢复。
- 出口测试是用户触发的小流量第三方请求；没有测试真实节点时，仅按节点名称标注选择同国，可能与实际出口不同。
- 控制接口只允许 Windows 命名管道及本机 HTTP/HTTPS；不接入远程内核。内核进程身份每 10 秒检查，用户切换前强制复查。其他控制工具与助手之间不存在跨进程事务锁，配置变更时请避免同时操作多个控制界面。
- 需要管理员权限的进程识别、真实 UDP/QUIC 应用、混合 DPI 多屏、安装/卸载及登录联动尚需人工验收。安装包未签名；未配置自动更新服务器。
